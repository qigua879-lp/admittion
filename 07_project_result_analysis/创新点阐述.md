# 创新点阐述：单向 MIPI CSI-2 链路上的行级选择性重采集

> 用途：论文绪论 1.2/1.3、开题/中期/答辩的"创新点定位"论证。
> **诚实声明**：本文第 2、3 节为**方法类别归纳**（领域常识层面），**未引用任何具体文献的具体结论**；
> 待作者文献清单归位后，按〔R 槽〕补入具体引用。
> 红线：不写"CSI-2 自动重传"；不写"已上板"。

---

## 1. 我们的创新点（一句话 + 三支柱）

**一句话**：面向**单向** MIPI CSI-2 链路，提出基于**错误上下文定位**的**行级选择性重采集机制**，
并给出其相比"整帧重传 / 整帧丢弃"在**内存开销与有效帧率**之间取得更优折中的**条件**与**量化边界**。

**三支柱**（对应三种贡献层次）：

| 支柱 | 内容 | 贡献性质 |
|---|---|---|
| **机制** | 错误定位（帧号+帧内行号）→ 重采集请求 → **按行号写回覆盖坏行原槽**，并推广至多帧 | 工程/系统贡献 |
| **量化边界** | 三策略（行级/整帧重传/整帧丢弃）内存-帧率-时延闭式模型；核心边界 **ρ = D/H** | 定量贡献 |
| **条件** | 单向链路补出行级恢复的**可行性条件 C1–C4** 及三条退化边界 | 理论贡献 |

---

## 2. 问题的根源：这是一个**结构性**空档

### 2.1 为什么单向链路不能"简单加个 ACK"
MIPI CSI-2 的高速数据通道（D-PHY lane）**被设计成单向**——为省引脚、省功耗、简化 PHY。
这不是疏漏，是权衡。因此**链路层不存在也不可能存在 ACK/NACK 重传**〔R1〕。

### 2.2 于是接收端只剩两条粗粒度退路
| 退路 | 代价 |
|---|---|
| **整帧丢弃** | 坏帧**永久丢失**（运动视频卡顿/撕裂）|
| **整帧重传**（需上游配合）| 需**整帧缓存** + **一帧恢复时延** |

**粒度困境**：一帧（1080 行）往往只有**极少数行**真正出错，却要按**整帧**付内存和时延。

### 2.3 被忽视的关键事实（本文的切入点）
**系统中其实早就存在一条反向通道——CCI/I²C**（本来用于 sensor 配置）。
它低速，但传几个字节的"重发第 N 帧第 M 行"请求**绰绰有余**。
> **本文的洞察**：链路保持单向不变，把"恢复能力"建在**已有的低速反向通道 + 可控图像源**之上，
> 从而把恢复粒度从"帧"细化到"行"。

## 3. 现有解决办法

### 3.1 学术界（按方法类别）

| 路线 | 思路 | 在本问题上的局限 | 引用槽 |
|---|---|---|---|
| **ARQ / SR-ARQ / HARQ** | 检错后请求重传；SR-ARQ 已有"只重传丢失单元"的选择性思想 | **前提是双向链路**。CSI-2 数据通道单向，直接不可用；且这些工作多在网络/链路层，未落到图像采集前端 | 〔R3〕 |
| **FEC（前向纠错）** | 发端加冗余（RS/LDPC 等），收端自纠 | **固定开销**：无论有没有错都要一直占带宽；纠错能力有上限，超出即失效 | 〔R3〕 |
| **错误隐藏（Error Concealment）** | 用空域/时域插值把丢失区域"猜"回来 | **引入失真**——恢复的不是原始数据，是估计值；对测量/工业视觉不可接受 | 〔R4〕 |
| **不等差错保护 / ROI 保护** | 对重要区域加强保护 | 仍是 FEC 变体，固定开销问题依旧；且需先知道哪里重要 | 〔R4〕 |

**学术界小结**：**"选择性重传"的思想是有的（SR-ARQ），但都假设双向链路**；
面向**单向图像采集链路**的**行级**细粒度恢复，缺少系统性的机制 + 条件 + 边界研究。

### 3.2 工程界（商用 IP 与实际做法）

| 做法 | 现状 | 局限 | 引用槽 |
|---|---|---|---|
| **商用 CSI-2 RX IP** | 提供包头 ECC（单比特纠错）、载荷 CRC 检错、错误标志/中断、错误计数 | **只"检出"，不"恢复"**——恢复策略留给上层 | 〔R2〕 |
| **上层的典型策略** | 检出错误 → **丢弃整帧**，等下一帧 | 粒度=帧，坏帧永久丢失 | 〔R2〕 |
| **包头 ECC** | 唯一真正的"纠错" | 只保护**包头**，且只纠单比特；**载荷（像素数据）不纠** | 〔R1〕 |
| **传感器侧重读** | 部分 sensor 支持经 I²C 触发重读/带帧缓存 | 粒度=**帧**，且业界未把它用于**行级**错误恢复闭环 | 〔R2〕 |

**工程界小结**：**可靠性止步于"检测 + 报告 + 丢帧"**。反向通道（I²C）被用来配置，
**没有被用来做数据恢复**。

### 3.3 空档定位（六维对比）

| 路线 | 需双向数据链路? | 恢复粒度 | 额外开销 | 引入失真? | 能恢复原始数据? |
|---|:--:|:--:|---|:--:|:--:|
| ARQ / SR-ARQ | **需要** ❌ | 包 | 按需（低误码≈0）| 否 | ✅ |
| FEC | 不需要 | — | **固定**（恒占带宽）| 否（能力内）| ✅（能力内）|
| 错误隐藏 | 不需要 | 像素/块 | 低 | **是** ❌ | ❌（估计值）|
| 整帧丢弃（工程常见）| 不需要 | 帧 | 0 | — | ❌ **永久丢失** |
| 整帧重传 | 需反向请求 | **帧** | **整帧缓存 + 一帧时延** | 否 | ✅ |
| **本文：行级重采集** | **仅需低速反向通道（已存在）** | **行** ✅ | **D·L 缓存 + D·T_l 时延** ✅ | 否 ✅ | ✅ |

> **空档一句话**：既要**保持链路单向**、又要**不引入失真地真正恢复原数据**、还要**粒度细到行**——
> 现有路线没有一条同时满足。本文填的就是这个格子。

## 4. 我们的方法（简述）

1. **定位**：ECC/CRC 检出坏行 → 绑定 `帧号 + 帧内行号 + VC/DT`；坏行被丢弃，帧缓冲留下**空槽**。
2. **请求**：锁存错误上下文，经低速反向通道（CCI/I²C）向上游**可控图像源**发出"重发第 N 帧第 M 行"。
3. **写回覆盖**：上游重发该行时，接收端**按行号寻址**把它写回**坏行原来的槽位**
   （不推进行计数器、不触发越界丢弃、幂等）——这是"只发请求"到"真正恢复"的关键一步。
4. **多帧成立**：用**帧内行号**（每帧复位）而非自由累加的行计数，保证任意帧都能映射到正确槽位。

## 5. 我们的优势（必须分对手说）

> ⚠️ 只说"省内存"是不够的——会被追问"加大 FIFO 不就行了？"。正确表述是**折中点整体优于两条基线**。

### 对手 A：整帧丢弃 → 我们赢在**可靠**
- 它：坏一行 → 丢整帧 → **永久丢失**，运动画面卡顿。
- 我们：坏行被**恢复**，**帧不丢**。这是纯粹的可靠性提升（从"丢"到"不丢"）。

### 对手 B：整帧重传 → 我们赢在**省**（三项都省 ≈ H/D 倍）
| 指标 | 整帧重传 | 行级重采集 | 优势 |
|---|---|---|---|
| 上游缓存 | 整帧 `F = H·L` | **`D·L`** | 省 **H/D** 倍 |
| 恢复时延 | 一帧 `T_f` | **`D·T_l`** | 省 **H/D** 倍 |
| 带宽余量需求 | `≈ 1 + H·p` | **`≈ 1 + p`** | 少 **≈H** 倍 |

### 对手 C：FEC → 我们赢在**按需**
FEC 是**固定开销**（没错也一直占带宽）；重采集是**按需开销**（低误码时几乎不花额外流量，
额外开销 = `F·p/(1-p)`，p→0 时趋于 0）。

### 对手 D：错误隐藏 → 我们赢在**真实**
错误隐藏给的是**猜出来的像素**（引入失真）；重采集拿回的是**原始真实数据**。

### 额外优势：**保持链路不变**
不需要修改 CSI-2 协议、不需要给数据通道加反向线——只用系统**已有**的低速控制通道。

## 6. 例子

### 6.1 功能例子：一次完整的恢复（仿真实测，可复现）

场景：一帧 RAW8，其中 **line2 被注入 CRC 错误**。

```
① 出错   → line2 的 CRC 校验失败
② 丢弃   → 坏行被丢，帧缓冲 slot2 = 空 (0x00000000 × 4)
③ 定位   → 绑定上下文：frame=1, 帧内行号=3 (对应 slot2)
④ 请求   → 发出行级重采集请求 (retry_pending 置位)
⑤ 重采   → 上游可控源重发 line2（干净数据）
⑥ 写回   → 按行号覆盖 slot2
⑦ 结果   → slot2 = 11 22 33 44  ← 与干净行完全一致
⑧ 收尾   → retry_pending 经 ack 清除
```

**关键证据**：`slot2` 从 **0（丢失）→ 11 22 33 44（恢复为正确数据）**。
若不做重采集（"整帧丢弃"基线），slot2 **永远是 0**。

**多帧证据**：第 2 帧的坏行被定位为"**帧内第 3 行**"（而非自由计数的第 7 行），
写回命中正确槽位——证明机制不局限于首帧。

### 6.2 数值例子（一）：同场景三策略实测对比（H=8，单坏行）

| 策略 | 恢复传输量 | 上游缓存 | 能否恢复 |
|---|---:|---:|:--:|
| **行级重采集（本文）** | **18 B**（1 行）| **1 行** | ✅ |
| 整帧重传 | 152 B（8 行）| 8 行 | ✅ |
| 整帧丢弃 | 0 | 0 | ❌ **永久丢失** |

→ 内存比 **1 : 8 = D : H**，与模型 **ρ = D/H** 精确吻合。

### 6.3 数值例子（二）：真实分辨率下的量级（1080p RAW10，D=8）

| 指标 | 整帧重传 | 行级重采集 | 差距 |
|---|---:|---:|:--:|
| 上游缓存 | **2.47 MB** | **18.75 KB** | **≈135×** |
| 恢复时延 | **33.3 ms**（一帧）| **247 µs** | **≈135×** |

### 6.4 数值例子（三）：为什么帧级策略在高分辨率下会"塌掉"

一帧有 **1080 行**，所以哪怕**单行错率只有 0.19%**（BER=1e-7）：

$$p_f = 1-(1-p)^{1080} \approx \mathbf{87\%}$$

**87% 的帧都带伤！** 于是：

| 策略 | 有效帧率（标称 30 fps）|
|---|---:|
| 整帧重传 / 整帧丢弃 | **3.77 fps** ← 崩溃 |
| **行级重采集** | **30 fps** ← 保持满帧率 |

> **这是最有说服力的数字**：行数越多（分辨率越高），帧级策略越不可用，
> 而行级策略的开销只跟**单行错率 p** 挂钩，与帧高 H 无关。

## 7. 失效边界（诚实声明——能说出边界才叫研究）

| 边界 | 条件 | 后果 |
|---|---|---|
| **ρ = D/H → 1** | 往返窗口 D 接近帧高 H（如上游只能整帧缓存）| 退化为整帧重传，优势消失 |
| **无反向通道 / 源不可重发** | C1、C2 不成立 | 只能整帧丢弃 |
| **注错密度 > 服务速率** | 单未决请求下两次坏行间未完成重采（C2）| 较早的行请求被覆盖 → 该行丢失 |
| **误码过高** | `h < 1/(1-p)`，带宽余量不足（C3）| 重发压垮帧率 |

（第 3 条已有仿真演示：连续两个坏行只重采一次时，后者恢复、前者丢失。）

---

## 8. 一句话总结

> 现有方案要么**需要双向链路**（ARQ），要么**固定开销**（FEC），要么**引入失真**（错误隐藏），
> 要么**粒度太粗**（丢帧/整帧重传）。本文在**保持 CSI-2 链路单向**的前提下，
> 借助**系统已有的低速反向通道 + 可控图像源**，把恢复粒度细化到**行**，
> 以 **1/H·D** 的内存与时延代价实现**无失真的真实数据恢复**，
> 并给出了该机制成立的**可行性条件**与**划算边界 ρ=D/H**。
