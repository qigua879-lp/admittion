## 1. 本文创新点（一句话 + 三支柱）

> 面向**单向** MIPI CSI-2 链路，提出基于错误上下文定位的**行级选择性重采集机制**，并给出其相比
> "整帧重传/整帧丢弃"在内存与有效帧率间更优折中的**条件**与**量化边界**。

- **机制**：错误定位 → 重采集请求 → **按行号写回覆盖**，且推广到多帧连续流。
- **量化边界**：三策略内存/帧率/时延闭式 + 划算边界 **ρ=D/H**（省 H/D 倍）。
- **条件**：单向链路补出行级恢复的四条可行性条件 C1–C4 及退化边界。

## 2. 领域现状（三块拼图，证明空档的精确位置）

### 2.1 学术界：选择性/部分重传——成熟，但都在【双向·无线·网络层】
无线视频传输领域对"细粒度重传"研究很深：
- **部分包恢复（partial packet recovery）**：包未过 CRC 时只重传出错比特，而非整包〔候选，待核实〕
- **感知加权 ARQ（perceptual ARQ, 802.11e）**：只重传感知最重要的包，降低重传带宽〔候选〕
- **UV-ARQ（uncompressed video ARQ）**：接收端只请求视频包中高重要度部分〔候选〕
- **优先级重传 / 多描述编码 + HARQ**：按重要度调度重传〔候选〕

**共同前提**：① 链路**双向**（有反向 ACK/NACK）；② 层次在**网络/应用层**（有包序号、重传缓冲协议）；
③ 关注**感知质量/带宽**，不涉及硬件帧缓冲的**写地址语义**。

### 2.2 工程界：缓存+重传相机——成熟商用，但都在【双向链路·帧级】
机器视觉相机已有"缓存+经控制通道触发重传"的商用功能：
- **Teledyne FLIR** 机器视觉相机：板载帧缓冲 + `IMAGE_RETRANSMIT` 寄存器（12E8h），经控制接口写入即
  **重发上一帧**；官方应用笔记明确用途之一为**"数据丢失或损坏时的图像重传"**〔工程锚点，已读应用笔记摘要，需引官方文档〕

**共同前提**：① 链路**双向**（USB3/GigE，有反向控制+数据握手）；② 重传粒度=**整帧**；
③ 面向"外部触发/带宽不足"场景，未做行级、未形式化可行性条件。

### 2.3 学术界：MIPI CSI-2 接收端研究——只做【检错】，不做【恢复】
CSI-2 接收端的研究关注点集中在实现与性能，**不涉及错误恢复机制**：
- 低功耗多 lane CSI-2 接收架构（8-Byte 并行协议层）〔候选，IEEE〕
- 基于 FPGA 的 UHD（4K@30）CSI-2 图像采集系统〔候选，IEEE〕
- 10 Gbps CSI-2 接收桥接芯片 / 各类 FPGA 实现与硕士论文〔候选〕
- 商用 CSI-2 RX IP（Cadence/Microchip/Intel/AMD）：可靠性=**ECC(1纠2检)+CRC16 检错**，坏包**丢弃**〔产品文档〕

**共同点**：可靠性含义是"长时间稳定接收/检错"，坏数据处理止于**丢弃**；**无错误恢复研究**。

### 2.4 相关但不同：行级错误隐藏（不是恢复）
- 存在"某行出错时用**前一行数据替换**"的行级错误隐藏方案（专利 US6330027 等）〔候选〕。
  **区别**：错误隐藏是**猜测/掩盖**（用邻行近似），本文是**取回真实数据**（重采集覆盖）。

## 3. 空档定位（三块拼图之间的精确缝隙）

```
选择性重传思想   →【双向】【无线】【网络层】【感知质量】     ✔成熟
帧级缓存+重传    →【双向链路】相机、粒度=【帧】             ✔商用（Teledyne）
CSI-2 接收端研究 →只做【检错+丢弃】，无恢复                ✔现状
行级错误隐藏     →【猜测替换】，非真实数据                  ✔存在
──────────────────────────────────────────────────────────
本文空档 = 【单向】传感器接口 + 【行级】真实数据重采集
          + 把上述思想落地所需的三个该领域特有新问题：
   ① 数据链路无反向通道 → 复用 CCI/I²C 并形式化时序条件（C2）
   ② 源端重传的缓冲语义 → 缓冲深度条件（C1）
   ③ 接收端帧缓冲写地址语义 → 行级写回覆盖（帧内行号+按槽覆盖）★网络层不存在此问题
```

> **定位金句（可直接用于 1.2.3 与 4.1）**：
> "选择性重传思想在无线视频领域已成熟，帧级缓存重传在双向链路相机中已有商用实现；但将其移植到
> **单向 MIPI CSI-2 传感器接口**并细化到**行级**，需解决该场景特有的反向通道时序、源缓冲语义与
> 接收端写地址语义三个新问题。本文给出机制、量化边界与可行性条件加以解决。"

## 4. 我们的优势（逐块对照）

| 对照对象 | 它的边界 | 本文优势 |
|---|---|---|
| 无线视频部分重传 | 双向、网络层、靠包协议 | 单向链路、链路层、复用已有 CCI 控制通道，无需协议改造 |
| Teledyne 帧级重传 | 双向、粒度=帧 | 单向前提下形式化其可行条件；**粒度=行**，省 H/D 倍缓存与时延 |
| CSI-2 接收端研究 | 只检错、坏数据丢弃 | 从"检出"推进到"行级恢复真实数据" |
| 行级错误隐藏 | 用邻行**猜** | 重采集**取回真实像素**（覆盖坏行槽）|

**三个"别人没有"的技术点**（写进贡献）：
1. **行级写回覆盖 + 帧内行号**：接收端帧缓冲的槽位覆盖语义——网络层重传里根本不存在这个问题。
2. **单向链路可行性条件 C1–C4 的形式化**：把"能不能补出行级恢复"变成可判定的定量前提。
3. **ρ=D/H 量化边界**：给出"何时行级划算/何时退化为帧级"的设计空间刻画。

## 5. 例子（印证价值，数值 + 功能各一）

### 5.1 数值例（省多少）
1920×1080 RAW10、往返窗口 D=8 行：
- 整帧重传需缓存整帧 ≈ **2.47 MiB**、恢复时延 ≈ **一帧 33 ms**；
- 行级重采集只需 **≈18.75 KiB**（D 行）、恢复时延 ≈ **247 µs**；
- **省约 135× 内存与恢复时延**（ρ=D/H=8/1080）。仿真同场景实测内存比 8×=H/D（H=8）与模型精确吻合。

### 5.2 功能例（能做什么/别人不能）
一帧中第 k 行 CRC 坏：
- **只丢弃**（现状）→ 坏帧永久丢失；
- **整帧重传**（Teledyne 级）→ 重发整帧，代价整帧缓存 + 一帧时延；
- **行级错误隐藏** → 用第 k−1 行**假装**是第 k 行（失真）；
- **本文行级重采集** → 上游经 CCI 请求只重发第 k 行 → 接收端**按行号覆盖回坏行原槽** → 取回**真实**第 k 行；
  仿真实证：坏行槽由空 → 被干净数据覆盖，且跨帧成立（帧内行号定位）。
