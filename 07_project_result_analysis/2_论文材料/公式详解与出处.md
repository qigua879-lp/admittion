# 第一部分：基础技术公式（第 2、3 章 · 均为标准结论）

## 式(2-1) 两级同步器的平均无故障时间 MTBF 🟦

```
MTBF = e^(t_r / τ) / (f_clk · f_data · T_w)
```

- **含义**：衡量跨时钟域用两级触发器同步时，多久才会发生一次"亚稳态没恢复完就被采走"的故障。
- **符号**：`t_r`=留给亚稳态恢复的时间（≈一个时钟周期减去建立时间）；`τ`=触发器的恢复时间常数；
  `T_w`=会进入亚稳态的"危险窗口"宽度；`f_clk`=采样时钟频率；`f_data`=异步数据的翻转频率。
- **推导来历**：亚稳态电压差随时间**指数衰减**（`ΔV ∝ e^(t/τ)`）。给的恢复时间 `t_r` 越长，残余亚稳态概率
  越小，呈 `e^(t_r/τ)`。故障率正比于"采样机会×翻转机会"`f_clk·f_data`，再乘危险窗口 `T_w`；MTBF 是它的倒数。
- **直觉**：分子 `e^(t_r/τ)` 是"给它越多时间冷静，越不容易出事"（指数级好转）；这就是**为什么加一级触发器
  （多给一个周期恢复）MTBF 会指数级改善**。
- **出处**：🟦 数字系统工程标准结论（Dally & Poulton《Digital Systems Engineering》；Cummings 关于 CDC 的经典文章）。**R5**。
- **用在**：2.3 跨时钟域；佐证综合里对同步器打 `ASYNC_REG` 属性的合理性。

## 式(2-2) ECC 汉明距离与纠错/检错能力 🟦

```
纠错能力  t_纠 = ⌊(d_min − 1) / 2⌋
检错能力  t_检 = d_min − 1
CSI-2 包头 d_min = 4  ⇒  单比特纠错、双比特检错（SECDED）
```

- **含义**：一个纠错码能纠几个错、能检几个错，只取决于码字之间的**最小汉明距离** `d_min`（两码字不同的比特数最小值）。
- **推导来历**：要把接收到的错码"归位"到最近的合法码字，纠 `t` 个错需要各合法码字周围半径 `t` 的球不相交，
  即 `d_min ≥ 2t+1`。只检不纠时，只要错误没把它变成**另一个**合法码字即可，故检 `d_min−1` 个。
- **CSI-2 用法**：CSI-2 长包**包头**（24 bit 数据 + 8 bit ECC）用汉明 SECDED，`d_min=4` → **单比特纠错、双比特检错**。
- **直觉**：距离越大，码字之间"隔得越开"，越不容易被噪声推到邻居身上。
- **出处**：🟦 编码理论（Hamming, 1950）+ MIPI CSI-2 规范定义了包头 ECC。**R6 + R1**。
- **用在**：2.4 差错检测；第 4 章误码模型里"检出坏行"的能力边界（ECC 管头、CRC 管载荷）。

## 式(2-3) CRC16 多项式除法余数检错 🟦

```
R(x) = ( M(x) · x^16 ) mod G(x)
G(x) = x^16 + x^12 + x^5 + 1      （CRC-CCITT）
接收端重算余数：= 0 认为无错，≠ 0 即检出错误
```

- **含义**：把整段载荷当成一个二进制多项式 `M(x)`，左移 16 位后除以固定的生成多项式 `G(x)`，余数 `R(x)` 就是 16 位 CRC。
  接收端把"数据+CRC"再除一遍 `G(x)`，**余数为 0 认为无错，非 0 即检出错误**。
- **推导来历**：多项式除法在 GF(2)（模 2 加 = 异或）下进行；`G(x)` 的次数和形状决定了能 100% 检出的错误类型
  （所有 ≤16 位突发错、所有奇数个错等）。
- **直觉**：CRC 是"给数据算一个高灵敏度指纹"，改动几乎必然改变指纹。
- **出处**：🟦 编码理论 + MIPI CSI-2 规范规定用 CRC-16（多项式如上）。**R6 + R1**。
- **用在**：2.4；第 4 章"坏行被 CRC 检出并丢弃 → 留空槽"的前提。

## 式(3-1) restoring 迭代除法递推 🟦

```
P_(i+1) = 2·P_i − q_i · Divisor ,   q_i ∈ {0, 1}
组合实现关键路径 O(n^2)  →  迭代实现每拍 O(n)（n 位商走 n 拍）
```

- **含义**：restoring（恢复余数）除法每拍求商的一位：部分余数 `P` 左移一位（×2），试减除数；够减商 1、不够
  商 0 并把减掉的加回来（"恢复"）。`n` 位商走 `n` 拍。
- **推导来历**：把一个组合实现里 `n` 级串起来的减法/比较（关键路径 `O(n^2)` 量级、极长）**拆成 `n` 个时钟周期**，
  每拍只做一级 `O(n)` 的加减——**用面积/周期数换极短的关键路径**。
- **为什么本文要它**：自适应预处理帧末要算若干个除法（如均值），组合除法是**时序杀手**。改成共享的迭代
  除法器 FSM 后，把 200MHz 下 WNS 从负拉回 **+0.194ns**（这条是第 5.7 节时序收敛的关键动作之一）。
- **出处**：🟦 计算机算术标准（Parhami《Computer Arithmetic》；Hennessy-Patterson 附录）。**R7**。
- **用在**：3.5 迭代除法器设计；5.7 时序收敛（对照）。

# 第二部分：第 4 章核心公式（除 4-6 外均为本文自推）

## 式(4-1) 基本量定义 🟥（定义）

```
L = W · bpp        （行字节数 = 行像素数 × 每像素字节数）
F = H · L          （帧字节数 = 帧行数 × 行字节数）
T_l = T_f / H      （行周期 = 帧周期 / 帧行数）
```

- **含义**：`L`=一行字节数；`F`=一帧字节数；`T_l`=一行时间（帧周期 `T_f` 均分到 `H` 行）。
- **出处**：🟥 本文符号定义，无需引用。
- **用在**：4.1.1；后面所有公式的地基。

## 式(4-2) 单行残余失效概率 p 🟦→🟥

```
p = 1 − (1 − BER)^(8L)  ≈  8L · BER
```

- **含义**：一行有 `8L` 个比特，每比特独立以位错误率 `BER` 出错；一行"全对"的概率是 `(1−BER)^(8L)`，
  所以"这一行失效"= `1 − (1−BER)^(8L)`。`BER` 很小时用一阶泰勒展开 ≈ `8L·BER`。
- **推导**：设各比特错误独立同分布 → 整行无错 = 各比特无错之积 → 取补。近似：`(1−x)^n ≈ 1−nx`（`x≪1`）。
- **直觉**：行越长（`L` 大）越容易踩到坏比特；这解释了高分辨率下每行更脆。
- **出处**：🟦 独立误码模型是概率论标准；🟥 用到"行"这个粒度上是本文的建模选择（"残余"=检出后仍失效）。
- **用在**：4.1.1；对照 5.5 误码实验。

## 式(4-3) 整帧含坏行概率 p_f 🟦→🟥

```
p_f = 1 − (1 − p)^H  ≈  H · p
```

- **含义**：一帧 `H` 行，每行独立以 `p` 失效；整帧"一行都不坏"= `(1−p)^H`，所以"整帧带伤"= 取补。`p` 小时 ≈ `Hp`。
- **关键洞察（全文最有杀伤力的一条）**：即使 `p` 极小，只要 `H` 大（高分辨率），`p_f` 也会趋近 1。
  代入 BER=1e-7、1080p RAW10：`p≈1.9e-3`，`p_f ≈ 1−(1−1.9e-3)^1080 ≈ 87%`——**87% 的帧都带伤**。
- **直觉**：帧级策略"一行坏就赔整帧"，行数越多越亏；这是**结构性**的，不是调参能救的。
- **出处**：🟦 独立模型标准；🟥 结论（帧级随 H 塌陷）是本文用来立论的关键。
- **用在**：4.1.1；直接支撑 4.3.2 的"帧级有效帧率崩溃"。

## 式(4-4) 往返窗口 D 🟥（本文自推 · 模型核心自变量）★

```
τ_rt = τ_det + τ_bc + τ_src          （往返时延 = 检出 + 反向通道 + 源响应）
D = ⌈ τ_rt / T_l ⌉                    （往返期间又流过的行数）
```

- **含义**：从"检出坏行"到"重发的行到达接收端"要走一个往返 `τ_rt`（检出 `τ_det` + 请求经反向通道 CCI/I²C
  传到源 `τ_bc` + 源定位并开始重发 `τ_src`）。把这段时间换算成"其间又流过几行"，就是 `D`。
- **推导**：数据链路不停流，往返期间流过的行数 = `τ_rt / T_l`，向上取整。
- **直觉**：`D` = 这套恢复机制的**反应窗口，用行数度量**。`D` 越小（检出快、反向通道快、源响应快）越好——
  它直接决定后面所有代价（内存 `D·L`、时延 `D·T_l`、边界 `ρ=D/H`）。仿真中 `D≈1`，解析代表值取 `D=8`。
- **出处**：🟥 **本文自推**，是整个量化模型的核心自变量。
- **用在**：4.2.4（时间链）、4.3（所有代价的自变量）、4.4（可行性条件）。

## 式(4-5) 帧内行号映射与错位量 🟥（本文自推 · 多帧判别依据）★

```
slot = line_in_frame − 1                        （写缓冲槽位，0 基）
line_cnt = ΣH_i + line_in_frame                 （同步 FSM 自由累加计数）
```

- **含义**：上半句——写缓冲的槽位（0 基）= 帧内行号（1 基）− 1，这是"重发行该覆盖哪个槽"的映射。
  下半句——同步 FSM 的**自由累加计数** `line_cnt` = 之前所有帧的总行数 `ΣH_i` + 当前帧内行号。
- **为什么会错位（本文修的 bug）**：只有**第一帧**（前面没有帧，`ΣH_i=0`）时 `line_cnt = line_in_frame`，朴素的
  `−1` 才对；第二帧起自由计数比帧内行号多 `ΣH_i`，用它寻址会覆盖到**错误的槽**。解法：用**帧内行号**（每帧复位）。
- **判别证据**：多帧仿真里，第 2 帧的坏行**帧内行号=3、自由计数=7**（=前帧 4 行 + 3）；用帧内行号才能命中正确槽。
- **出处**：🟥 **本文自推**，源自对 RTL 计数语义的分析；是可行性条件 C4 的 RTL 闭合。
- **用在**：4.2.5 多帧推广；对照 5.3.2 多帧判别实验。

## 式(4-6) 期望传输次数 E[N] 🟦（几何分布 · 标准结论）

```
P(N = k) = p^(k−1) · (1 − p)                    （第 k 次才成功）
E[N] = Σ_{k≥1} k · p^(k−1) · (1 − p) = 1 / (1 − p)
```

- **含义**：一个单元（行或帧）以概率 `p` 失败、失败就重发直到成功，传输次数 `N` 服从**几何分布**；期望是 `1/(1−p)`。
- **推导（两种，答辩都能用）**：
  - **方法一（级数）**：`E[N] = (1−p)·Σ k·p^(k−1)`，用幂级数求导恒等式 `Σ k·p^(k−1) = 1/(1−p)^2`，代回得 `1/(1−p)`。
  - **方法二（自指递推，一行到底）**：第一次要么成功（用 1 次），要么失败（浪费 1 次再从头）：
    `E[N] = (1−p)·1 + p·(1 + E[N]) = 1 + p·E[N]  ⇒  E[N] = 1/(1−p)`。
- **直觉**：`p→0` 时 `E[N] ≈ 1+p`，几乎一次成功；且**"重发又坏、再重发"已全部计入**。
- **出处**：🟦 概率论标准（几何分布期望）。**R3**。
- **用在**：4.3.1；是式(4-7) 开销的来源。

## 式(4-7) 额外传输开销 🟥（本文自推 · 由 4-6）

```
每单元额外次数 = E[N] − 1 = p / (1 − p)
行级额外流量 = F · p / (1 − p)
帧级额外流量 = F · p_f / (1 − p_f)
```

- **含义**：为恢复而**多发**的流量。每个单元额外发 `E[N]−1 = p/(1−p)` 次。
  行级：`H` 行、每行额外、每行 `L` 字节 → `H·L·p/(1−p) = F·p/(1−p)`；帧级：整帧以 `p_f` 重发 → `F·p_f/(1−p_f)`。
- **关键对比**：行级开销 ∝ `p`（单行错率），帧级 ∝ `p_f ≈ Hp`——**帧级多花约 H 倍流量**。
  这正是仿真里单坏行"行级 18B vs 帧级 152B（≈8.4×，H=8）"的统计版本。
- **出处**：🟥 本文自推。
- **用在**：4.3.1；对照 5.4 三基线流量。

## 式(4-8) 满帧率的带宽余量条件 🟥（本文自推）

```
行级：h ≥ 1 / (1 − p)
帧级：h ≥ 1 / (1 − p_f)
```

- **含义**：`h`=链路带宽余量系数（标称数据之外还能多传的倍数）。要在重发的同时**仍维持标称帧率**，
  余量必须能吸收额外流量：行级只需 `1/(1−p)`，帧级需 `1/(1−p_f)`（大得多）。
- **推导**：由 4-7，维持吞吐 = 有效数据速率 ≤ 链路容量；把额外开销折进速率即得阈值。
- **直觉**：帧级"多花 H 倍"意味着它对带宽余量的要求也苛刻 H 倍量级——余量不够时帧率就掉。
- **出处**：🟥 本文自推。
- **用在**：4.3.2；也是可行性条件 C3（式4-15）。

## 式(4-9) 三策略有效帧率 🟥（本文自推）

```
f_A ≈ f_0            （行级：每坏行独立恢复、与 H 无关，保持标称帧率）
f_C = f_0 · (1 − p_f)（只丢：只剩干净帧比例）
f_B → 塌到与 f_C 同量级（整帧重传：带宽被整帧重发吃掉 / 等待整帧）
```

- **代表数**（30fps、`p_f≈87%`）：`f_C = 30 × 0.126 ≈ 3.77 fps`；`f_A ≈ 30 fps`。
- **出处**：🟥 本文自推。
- **用在**：4.3.2；对照 5.4、图 4-5。

## 式(4-10) 三策略内存开销 🟥（本文自推 · 由 C1）

```
ΔM_A = D · L         （行级：只备往返窗口 D 行）
ΔM_B = F = H · L     （整帧重传：留整帧）
ΔM_C = 0             （只丢：不留）
```

- **含义**：为支持恢复，上游/接收端要多备的缓存。行级只需覆盖往返窗口 `D` 行（由 C1）；整帧要留整帧；丢弃不留。
- **出处**：🟥 本文自推（依赖 C1，见 4-13）。
- **用在**：4.3.3；对照 5.4 的 `buffer_lines`。

## 式(4-11) 三策略恢复时延 🟥（本文自推）

```
T_A = D · T_l              （行级：往返窗口 D 行时间）
T_B ≈ T_f = H · T_l        （整帧重传：约一帧时间）
```

- **诚实标注**：仿真实测延迟比是 2.1× 而非模型的 8×——因为背靠背仿真无帧间空闲，绝对延迟压缩；论文如实说明。
- **出处**：🟥 本文自推。
- **用在**：4.3.3；对照 5.4（含偏差讨论）。

## 式(4-12) 核心边界 ρ=D/H 🟥（本文自推 · **核心贡献**）★★

```
内存比 = ΔM_A / ΔM_B = (D·L) / (H·L) = D / H
时延比 = T_A  / T_B  = (D·T_l)/(H·T_l) = D / H
       ⇒   ρ = D / H       优势倍数 = H / D
```

- **含义**：把 4-10、4-11 两两相除，`L`、`T_l` 全约掉——**内存比 = 时延比 = ρ = D/H**。行级相对整帧省 `H/D` 倍。
- **判据**：`ρ ≪ 1`（D≪H，往返窗口远小于整帧）时行级**严格更优**；`ρ→1` 时退化为整帧重传。
- **代表数**：1080p RAW10、D=8 → `ρ = 8/1080 ≈ 0.0074` → 省 **135×**（内存 2.47MB→18.75KB、时延 33.3ms→247µs）。
- **出处**：🟥 **本文自推，是全文最核心的一条边界**——答辩必讲。
- **用在**：4.3.4；对照 5.5 的 D 扫描。通俗展开见 midterm 文档第三部分。

## 式(4-13) 可行性条件 C1 —— 源缓存深度 🟥（本文自推）

```
B_src ≥ D + 1
```

- **含义**：上游可控源必须至少缓存**最近 D+1 行**，这样当请求经过 `D` 行的往返绕回来时，坏行**还在源缓存里**、能被重发。
- **直觉**：这就是"行级只需 D 行缓存"的根据——把整帧缓存的要求，砍到只覆盖往返窗口。
- **出处**：🟥 本文自推（对上游器件提出的**设计指标**，不是假设——这点答辩很有用）。
- **用在**：4.4.1；对照 5.5。

## 式(4-14) 可行性条件 C2 —— 活性/时间窗 🟥（本文自推）

```
τ_det + τ_bc ≤ B_src · T_l
```

- **含义**：检出 + 请求传播的时间，必须在源缓存能覆盖的时间窗 `B_src·T_l` 之内；否则请求还没到，坏行已被新数据
  **挤出源缓存**，无法重发。
- **注错密度限制**：单未决请求下，两个坏行之间必须留出完成一次重采的时间，否则较早的请求被覆盖 → 那行丢失
  （5.5.2 已仿真演示：双错单未决时，后者恢复、前者丢失）。
- **出处**：🟥 本文自推。
- **用在**：4.4.1；对照 5.5.2 时间窗实验。

## 式(4-15) 可行性条件 C3 —— 带宽余量 🟥（本文自推）

```
h ≥ 1 / (1 − p)
```

- **含义**：即式(4-8) 的行级情形——链路要有足够余量吸收重发流量，才能维持满帧率。与帧级要求差约 `H` 倍。
- **出处**：🟥 本文自推。
- **用在**：4.4.1。

## 式(4-16) 可行性命题 🟥（本文自推 · **理论贡献**）★★

```
( C1 ∧ C2 ∧ C3 ∧ C4 )  ⇒  行级重采集可恢复，且代价上界：
        内存 ≤ D · L      时延 ≤ D · T_l      额外流量 ≤ F · p / (1 − p)
```

- **含义**：只要四个条件同时成立（C1 源缓存够深、C2 请求在时间窗内、C3 带宽余量足、C4 帧内行号正确寻址），
  则行级重采集**保证能恢复真实数据**，且三项代价有**明确上界**。
- **推导**：把 4-10~4-15 组合——C1/C2 保证坏行可被重发且写回命中，C3 保证不掉帧率，C4（式4-5）保证多帧寻址正确；
  代价上界直接由 4-10/4-11/4-7 给出。
- **三条退化边界**（对应 5.4 三基线）：C1 失效 → 退整帧重传；反向通道失效 → 退整帧丢弃；ρ→1 → 退整帧重传。
- **出处**：🟥 **本文自推**，是"条件"这根支柱的形式化落点——最有学术味的一条。
- **用在**：4.4.2；对照 5.4 三退化边界。
