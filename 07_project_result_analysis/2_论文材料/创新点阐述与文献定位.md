## 1. 创新点（一句话 + 三支柱）

**一句话**：面向**单向** MIPI CSI-2 链路，提出基于**错误上下文定位**的**行级选择性重采集机制**，
并给出其相比"整帧重传 / 整帧丢弃"在**内存开销与有效帧率**之间取得更优折中的**条件**与**量化边界**。

| 支柱 | 内容 | 贡献性质 |
|---|---|---|
| **机制** | 错误定位（帧号+帧内行号）→ 重采集请求 → **按行号写回覆盖坏行原槽**，并推广至多帧 | 工程/系统贡献 |
| **量化边界** | 三策略（行级/整帧重传/整帧丢弃）内存-帧率-时延闭式模型；核心边界 **ρ = D/H** | 定量贡献 |
| **条件** | 单向链路补出行级恢复的**可行性条件 C1–C4** 及三条退化边界 | 理论贡献 |

## 2. 问题的根源：一个**结构性**空档

### 2.1 为什么单向链路不能"简单加个 ACK"
MIPI CSI-2 的高速数据通道（D-PHY lane）**被设计成单向**——为省引脚、省功耗、简化 PHY。
这是权衡而非疏漏，因此**链路层不存在也不可能存在 ACK/NACK 重传**〔R1〕。

### 2.2 于是接收端只剩两条粗粒度退路
| 退路 | 代价 |
|---|---|
| **整帧丢弃** | 坏帧**永久丢失**（运动视频卡顿/撕裂）|
| **整帧重传**（需上游配合）| 需**整帧缓存** + **一帧恢复时延** |

**粒度困境**：一帧（1080 行）往往只有**极少数行**真正出错，却要按**整帧**付内存和时延。

### 2.3 被忽视的关键事实（本文切入点）
系统中其实早就存在一条反向通道——**CCI/I²C**（本用于 sensor 配置）。它低速，但传几个字节的
"重发第 N 帧第 M 行"请求绰绰有余。
> **本文洞察**：链路保持单向不变，把"恢复能力"建在**已有的低速反向通道 + 可控图像源**之上，
> 从而把恢复粒度从"帧"细化到"行"。

## 3. 现有解决办法（含文献调研）

### 3.1 学术界：MIPI CSI-2 接收端研究——只做【检错】，不做【恢复】
CSI-2 接收端研究关注实现与性能：低功耗多 lane 架构、FPGA UHD(4K@30) 采集系统、10 Gbps 接收桥接
芯片等〔R2，候选，待核实〕；商用 RX IP（Cadence/Microchip/Intel/AMD）的可靠性=**ECC(1纠2检)+CRC16
检错**，坏包**丢弃**〔产品文档〕。**可靠性含义是"长时间稳定接收/检错"，无错误恢复机制研究。**

### 3.2 学术界：选择性/部分重传——成熟，但都在【双向·无线·网络层】
无线视频领域对细粒度重传研究很深：**部分包恢复**（只重传出错比特）、**感知加权 ARQ(802.11e)**、
**UV-ARQ**（只请求视频包中高重要度部分）、优先级重传/多描述编码+HARQ〔R3/R4，候选，待核实〕。
**共同前提**：① 链路**双向**（有反向 ACK/NACK）；② 层次在**网络/应用层**（有包序号、重传协议）；
③ 关注感知质量/带宽，**不涉及硬件帧缓冲的写地址语义**。

### 3.3 工程界：缓存+重传相机——成熟商用，但都在【双向链路·帧级】
机器视觉相机已有"缓存+经控制通道触发重传"的商用功能：**Teledyne FLIR** 机器视觉相机板载帧缓冲 +
`IMAGE_RETRANSMIT` 寄存器（12E8h），经控制接口写入即**重发上一帧**，官方应用笔记明确用途之一为
**"数据丢失或损坏时的图像重传"**〔工程锚点，已读应用笔记摘要，引官方文档〕。
**共同前提**：① 链路**双向**（USB3/GigE）；② 粒度=**整帧**；③ 未做行级、未形式化可行性条件。
> 这条锚点对本文**有利**：证明"缓存+反向通道触发重发"工程可行且已商用 → 本文条件 C1 不是空想，
> 基线 B（整帧重传）是真实实践而非稻草人。本文是把它从**帧级**推进到**行级**、并补上单向链路的形式化条件。

### 3.4 相关但不同：行级错误隐藏——【猜测】不是【恢复】
存在"某行出错时用**前一行数据替换**"的行级错误隐藏（专利 US6330027 等）〔R4，候选〕。
**区别**：错误隐藏是**猜测/掩盖**（用邻行近似，引入失真），本文是**取回真实数据**（重采集覆盖）。

### 3.5 六维对比与空档定位
| 路线 | 需双向数据链路? | 恢复粒度 | 额外开销 | 引入失真? | 恢复原始数据? |
|---|:--:|:--:|---|:--:|:--:|
| ARQ / SR-ARQ | **需要** ❌ | 包 | 按需（低误码≈0）| 否 | ✅ |
| FEC | 不需要 | — | **固定**（恒占带宽）| 否（能力内）| ✅（能力内）|
| 错误隐藏 | 不需要 | 像素/块 | 低 | **是** ❌ | ❌（估计值）|
| 整帧丢弃（工程常见）| 不需要 | 帧 | 0 | — | ❌ **永久丢失** |
| 整帧重传（Teledyne 级）| 需反向请求 | **帧** | **整帧缓存 + 一帧时延** | 否 | ✅ |
| **本文：行级重采集** | **仅需低速反向通道（已存在）** | **行** ✅ | **D·L 缓存 + D·T_l 时延** ✅ | 否 ✅ | ✅ |

```
空档 = 【单向】传感器接口 + 【行级】真实数据重采集
      + 落地所需的三个该领域特有新问题：
   ① 数据链路无反向通道 → 复用 CCI/I²C 并形式化时序条件（C2）
   ② 源端重传的缓冲语义 → 缓冲深度条件（C1）
   ③ 接收端帧缓冲写地址语义 → 行级写回覆盖（帧内行号+按槽覆盖）★网络层不存在此问题
```
> **定位金句（可直接用于 1.2.3 与 4.1）**：选择性重传思想在无线视频领域已成熟，帧级缓存重传在
> 双向链路相机中已有商用实现；但将其移植到**单向 MIPI CSI-2 传感器接口**并细化到**行级**，需解决
> 反向通道时序、源缓冲语义与接收端写地址语义三个新问题。本文以机制、量化边界与可行性条件解决之。

### 3.6 修正声明（前期结论纠偏）
本文前期曾断言"工程界无人用反向通道做恢复""学术界未做部分重传"——经调研**均不成立**：工程界已有
Teledyne 帧级重传、学术界已有无线视频部分重传。**修正后空档更精确**：本文的差异不在"重传/选择性"
这个思想，而在"**单向链路 + 行级 + 写地址语义 + 可行性条件形式化**"。

## 4. 本文方法（简述）
1. **定位**：ECC/CRC 检出坏行 → 绑定 `帧号 + 帧内行号 + VC/DT`；坏行被丢弃，帧缓冲留**空槽**。
2. **请求**：锁存错误上下文，经低速反向通道（CCI/I²C）向上游**可控图像源**发出"重发第 N 帧第 M 行"。
3. **写回覆盖**：上游重发该行时，接收端**按行号寻址**写回**坏行原槽**（不推进行计数、不越界丢弃、
   幂等）——"只发请求"到"真正恢复"的关键一步。
4. **多帧成立**：用**帧内行号**（每帧复位）而非自由累加计数，保证任意帧映射到正确槽位。

---

## 5. 优势（分对手说）
> ⚠️ 只说"省内存"会被追问"加大 FIFO 不就行了"。正确表述是**折中点整体优于所有基线**。

- **对整帧丢弃 → 赢在可靠**：它坏一行丢整帧、永久丢失；本文恢复坏行、帧不丢。
- **对整帧重传（Teledyne 级）→ 赢在省**：上游缓存 `D·L` vs `F=H·L`、恢复时延 `D·T_l` vs `T_f`、
  带宽余量 `≈1+p` vs `≈1+H·p`——三项均省 **≈H/D 倍**。
- **对 FEC → 赢在按需**：FEC 固定开销（没错也占带宽）；重采集按需，额外开销 `F·p/(1-p)`，p→0 趋于 0。
- **对错误隐藏 → 赢在真实**：隐藏给猜测像素（失真）；重采集拿回原始真实数据。
- **额外**：**保持链路不变**——不改 CSI-2 协议、不加反向数据线，只用已有低速控制通道。

## 6. 例子
### 6.1 功能例（仿真实测，可复现）
一帧 RAW8，line2 注入 CRC 错误：
```
①出错 → line2 CRC 失败  ②丢弃 → slot2 = 空(0×4)  ③定位 → frame=1,帧内行号=3
④请求 → retry_pending 置位  ⑤重采 → 上游重发 line2(干净)  ⑥写回 → 按行号覆盖 slot2
⑦结果 → slot2 = 11 22 33 44（与干净行一致）  ⑧收尾 → retry_pending 经 ack 清除
```
**证据**：slot2 由 **0（丢失）→ 11 22 33 44（真实数据恢复）**；不重采则永远是 0。
**多帧证据**：第 2 帧坏行定位为"帧内第 3 行"（非自由计数第 7 行），写回命中正确槽。

### 6.2 数值例一：同场景三策略实测（H=8，单坏行）
| 策略 | 恢复传输量 | 上游缓存 | 能否恢复 |
|---|---:|---:|:--:|
| **行级重采集（本文）** | **18 B**（1 行）| **1 行** | ✅ |
| 整帧重传 | 152 B（8 行）| 8 行 | ✅ |
| 整帧丢弃 | 0 | 0 | ❌ 永久丢失 |
→ 内存比 **1:8 = D:H**，与模型 **ρ=D/H** 精确吻合。

### 6.3 数值例二：真实分辨率量级（1080p RAW10，D=8）
| 指标 | 整帧重传 | 行级重采集 | 差距 |
|---|---:|---:|:--:|
| 上游缓存 | **2.47 MB** | **18.75 KB** | **≈135×** |
| 恢复时延 | **33.3 ms** | **247 µs** | **≈135×** |

### 6.4 数值例三：为什么帧级策略在高分辨率下"塌掉"（最有说服力）
一帧 1080 行，哪怕单行错率仅 0.19%（BER=1e-7）：
$$p_f = 1-(1-p)^{1080} \approx \mathbf{87\%}\ \text{的帧都带伤}$$
| 策略 | 有效帧率（标称 30 fps）|
|---|---:|
| 整帧重传 / 整帧丢弃 | **3.77 fps** ← 崩溃 |
| **行级重采集** | **30 fps** ← 保持满帧率 |
> 行数越多（分辨率越高）帧级越不可用；行级开销只跟单行错率 p 挂钩、与帧高 H 无关。

## 7. 失效边界（能说出边界才叫研究）
| 边界 | 条件 | 后果 |
|---|---|---|
| **ρ=D/H → 1** | 往返窗口 D 接近帧高 H（上游只能整帧缓存）| 退化为整帧重传 |
| **无反向通道/源不可重发** | C1、C2 不成立 | 只能整帧丢弃 |
| **注错密度 > 服务速率** | 单未决请求下两坏行间未完成重采（C2）| 较早行请求被覆盖→丢失 |
| **误码过高** | `h<1/(1-p)`，带宽余量不足（C3）| 重发压垮帧率 |
（第 3 条已有仿真演示：连续两坏行只重采一次时，后者恢复、前者丢失。）

## 9. 一句话总结
> 现有方案要么**需双向链路**（ARQ），要么**固定开销**（FEC），要么**引入失真**（错误隐藏），
> 要么**粒度太粗**（丢帧/整帧重传，Teledyne 已达帧级）。本文在**保持 CSI-2 链路单向**前提下，
> 借助**系统已有的低速反向通道 + 可控图像源**，把恢复粒度细化到**行**，以 **D/H** 的内存与时延代价
> 实现**无失真的真实数据恢复**，并给出机制成立的**可行性条件**与**划算边界 ρ=D/H**。
